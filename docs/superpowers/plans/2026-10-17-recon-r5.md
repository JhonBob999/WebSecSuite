# Recon R5 implementation plan

**Goal:** Connect one confirmed Nmap localhost self-test to the existing Recon runtime and asset inventory.

**Spec:** The supplied “WebSecSuite — Recon R5: First Live Tool Integration (Nmap)” request.

**Architecture:** Keep discovery passive. Use a contained, bounded version probe after explicit executable approval, then a separately confirmed immutable scan request. Reuse ExecutionPolicy, ProcessSupervisor, the R3 XML parser and AssetInventory.import_batch.

**Constraints:** Windows 11; existing Python/PySide6 venv; no new dependencies; no external scans; no arbitrary arguments; no changes to ScraperTaskManager or generated UI; no commit or push.

## Tasks and ownership

- [x] Preflight: branch bugfix/dec-20-pack, HEAD 52ba30d, R4.1 committed, clean reported working tree.
- [x] Windows runtime: add suspended native launch, assign a kill-on-close Job Object before resume; preserve the supervisor lifecycle, output bounds and non-Windows QProcess model. Prove startup, completion, failures, cancellation, timeout, descendant cleanup and shutdown with harmless local fixtures.
- [x] Trusted Nmap adapter: approve an absolute local nmap.exe path, verify identity/version, bind verification to file identity, issue one-use local authorizations and fixed plans. Preserve domain ScopeApproval rules. Normalize only the exact harmless Nmap DOCTYPE on trusted live output; keep offline import unchanged.
- [x] Runtime controller: create core/recon/nmap_runtime.py. NmapRuntime owns one ProcessSupervisor and exposes changed/inventory_changed signals, busy/can_run/status/executable_path/version/safety_reason properties, approve_executable(path), start_self_test(confirmed, target), stop(), shutdown(immediate=False). Never execute during construction. Import only complete validated successful results; preserve zero counts and history/provenance.
- [x] Tool Manager: extend the existing Nmap entry with explicit setup, version/path, gated Local Self-Test, Stop and terminal status. Confirm exact localhost/ports/technique/effects on every run. Other tools remain detection-only.
- [x] Integration and review: focused tests first, independent review of containment/authorization/XML/import boundaries, full pytest command and git diff --check, controlled Windows GUI startup, report actual Nmap availability and whether executed.

## Review focus

- Executable replacement after verification must invalidate scan preparation and queued preflight.
- Descendants created immediately, or left after parent exit, must remain contained and be terminated.
- Closing the app without another event-loop turn must still terminate the native job tree.
- XML errors, malicious declarations, incomplete output and rejected authorization must not mutate inventory/history.
- Repeated completion callbacks and identical run output must not create duplicate imports.

## Validation

Use PYTHONDONTWRITEBYTECODE=1 and the existing venv. Run `python -m pytest -q -p no:cacheprovider` and `git diff --check`. Do not execute Nmap scans automatically in tests or GUI initialization. Actual Nmap scanning requires the per-run localhost confirmation.
